# The editor (phase 2)

Design decisions for the native editor, agreed with Jiri milestone by milestone ([plan](plan.md), phase 2). Each milestone starts with its open questions; this page records what is settled.

## M1. The editor shell (done)

**Settled (2026-10-16):**

- **Inside the game app.** The editor is its own crate (`crates/editor`) that the game opens as a mode: a main-menu "Editor" entry and `canopy edit`. It does nothing until opened: no threads, no loading, no effect on start-up or frames for players.
- **UI: egui with egui_dock** for the editor chrome; the game renderer draws the 3D viewport into a texture the editor shows. The game's HUD keeps its own toolkit.
- **Look: a tool look as close to Tailwind's zinc palette as egui allows** (neutral zinc surfaces, 1-pixel borders, compact controls, rounded corners, subtle hover and focus states). The old spell studio's UI is the reference to match; the other old editors are not.
- **Navigation: a Slack-style rail.** A slim icon rail on the left switches between editors (maps, units and heroes, abilities, effects, items and buildings, races and rules, assets, later campaigns). Each editor keeps its own tabs and state; cross-links (a hero's "add ability → new") switch editors and come back.
- **MCP: in Rust (`rmcp`), hosted by the editor.** When the editor opens it can start its MCP server (a setting, or a toolbar toggle), over Streamable HTTP on loopback (`127.0.0.1`), with Origin and Host checks and a per-install token; it stops with the editor. `canopy mcp` runs the same server headless (no window) for agent-only work. MCP may write only inside the repository's base package.
- **It edits the repository, nothing else.** The editor works on the base package of the repository checkout the game runs from (`--data`, `just edit`). A game without one (every installed copy) shows the Editor entry disabled, and `canopy edit` refuses. Players' maps and mods are not edited for now (phase 2's players' content milestone).
- **One command set.** Every edit is a typed command; the editor's own controls, MCP clients and the built-in assistant all use it, so all of it is undoable and scriptable.
- **The assistant** (later milestone): a sidebar on the right that opens from the toolbar over any editor, as in the old spell studio; one assistant with access to every editor and threads per topic. It calls the Claude API directly (needs an API key; not covered by a Claude Code subscription); the shell leaves room for its panel.

**Settled (2026-10-16): the editing model.**

- **One undo history across all editors.** Commands group into steps (a transaction: "new ability + bind it to the Marshal" is one step, across files). Undo and redo bring back the context of the step: they switch to its editor, open or focus its tab and select what it changed.
- **Edits live in memory; Cmd+S saves everything.** Changed documents show an unsaved mark; Cmd+S (and MCP's `save`) writes every changed file. Leaving the editor (Exit, closing the window) with unsaved changes asks first.
- **Files changed on disk reload.** A watcher (`notify`) follows the base package: a document without unsaved edits reloads quietly; one with unsaved edits shows the conflict and asks which side to keep.
- **One file format, written in place.** Documents keep their key order (serde_json's `preserve_order`) and are written as 2-space JSON with a trailing newline, the format nearly every document already has; a test keeps every document in it, so a save's diff is only what changed.
- **The loader checks after every step.** The full load (about 90 ms) runs after each step and keeps a problems list that links to the element and field. Invalid states are allowed while working; saving with problems warns.
- **Renames carry their references.** Renaming an id rewrites every reference in the package in the same step; deleting something still referenced is refused, with where it is used.

**Settled (2026-10-16): schemas, viewport, testing.**

- **Schemas from the Rust types** (`schemars`): the content crate's serde types produce JSON Schema. It drives the inspector's forms, MCP's tool definitions and the skills' checks. Fields that name another element say so in the types (a unit id, an effect), so forms show a searchable picker and renames find every reference.
- **Generic forms, custom panels where they pay.** Every element gets a form from its schema; hand-built panels sit on top where a form is not enough (the ability timeline and encounter stage, the map tools).
- **One viewport widget.** The game renderer draws a scene into a texture sized to the panel; camera (orbit, top-down, the game's), picking and an overlay for gizmos are shared by every editor that shows a scene. One renderer serves whichever viewport shows. Each step updates the running preview in place. Previews stand on a zinc stage, with a switch to a biome's terrain.
- **Test in game runs what is open, unsaved edits included**, in-process: the game's data built from the editor's documents, a skirmish on the open map (or the last one), Esc back to the editor as it was, with the match tools (speed, reveal) and testing cheats. Editors may need their own loops beyond this (the map editor, the ability stage): decided with them.

**Build order:** (1) documents and commands: key order kept, the global undo with its context, Cmd+S, asking before leaving, the file-format check; (2) the loader's check after every step and the problems list; (3) the file watcher; (4) schemas, generic forms with reference pickers, renames; (5) MCP over the commands; (6) the viewport; (7) Test in game.

**Built (2026-10-16): the shell, read-only.** `crates/editor`, opened from the main menu's Editor entry, `canopy edit` or `just edit`. The rail switches seven editors; each lists its collections from the base package with the loader's own walk, opens documents as egui_dock tabs (read-only JSON for now) and shows the open one in its inspector. Undo, save, MCP, Test in game and the assistant are there as disabled controls. The theme is `crates/editor/src/theme.rs`; icons are drawn strokes (`icons.rs`), no icon font. It uses the game's interface font (Outfit). `canopy capture-screens --only editor` renders it offscreen in a few states.

**Built (2026-10-16): step 1, documents and commands** (`crates/editor/src/document.rs`). Edits are `Command`s (set, insert, remove, create, delete) on JSON pointers, grouped into steps; one history across editors, and undo or redo switches to the step's editor and tab. Removing a field and undoing puts it back in its place, so files keep their key order (D55). Cmd+S writes every changed document; the tab, the library row and the header mark unsaved ones; Exit and closing the window ask first. For now the inspector edits an element's name and the tab edits its JSON (Apply); forms come with step 4. A test keeps every base document in the file format.

**Built (2026-10-16): step 2, the check after every step** (`checker.rs`). A package can carry an overlay of documents that stand in for its files while it loads (`Package::with_overlay`); the editor lays its unsaved documents over the base package and runs the full load on a worker thread after each step (about 45 ms). The status bar shows the outcome; its list links each problem to its document. Saving with problems asks first.

**Built (2026-10-16): step 3, files changed on disk** (`watch.rs`, `notify`). A document without unsaved edits follows its file (its undo steps are dropped, as they were made against a version that is gone); one with unsaved edits becomes a conflict, and the editor asks which version to keep. Libraries are read again and the check reruns when files change; a file that is not valid JSON is reported and left alone.

**Built (2026-10-16): step 4, schemas, forms, references** (`content/src/schema.rs`, `forms.rs`, `references.rs`, `tabs.rs`, `inspector.rs`). Every content type derives `schemars::JsonSchema` (hand-serialized types have hand-written schemas; ids are `format: canopy-id`); `schema::of_document` shapes them like the files. A tab shows its document as a form (or its JSON): fields in schema order, enums and tagged variants as menus, ids with a searchable picker, add and remove for optional fields, list entries and map keys, numbers that fold a drag into one undo step; documents without a schema (behaviour sets, biomes, maps for now) get a form from their values. Undo marks the field it changed. The inspector lists where the element's id is used; Rename id rewrites every use (values and keys, in place) in one step; Delete is refused while anything uses it; the library's + creates an element from its schema's required fields.

**Built (2026-10-16): step 5, MCP** (`mcp.rs`, `shell/serve.rs`). `rmcp`'s Streamable HTTP server on `127.0.0.1:7431/mcp`, served by hyper on its own thread; Host must be loopback, any Origin is refused, and requests carry the per-install token (`editor-mcp-token` in the user folder). Tools: `status`, `list_elements`, `read_document`, `document_schema`, `edit` (commands as one undo step), `undo`, `redo`, `save` (refused with problems unless forced), `problems` (waits for the check), `find_uses`, `rename_id`. Calls run on the editor's thread with its documents, so agents' steps undo and show like the user's. The header's MCP chip opens a panel to start and stop it, set "start with the editor" (`editor.json`), and copy the `claude mcp add` command. `canopy mcp` (`just mcp`) runs the same server without a window.

**Built (2026-10-16): step 6, the viewport** (`stage.rs`). The game's renderer, a second instance owned by the editor, draws into a texture sized to the panel that egui shows; it is made when a viewport first shows. For now the inspector shows the open element's model (a definition's look, an asset or scenery model, from the last load that passed the check) on the zinc stage with an orbit camera (drag to turn, scroll to zoom, double-click to reset); a step that changes the look shows once its check passes.

**Built (2026-10-16): step 7, Test in game.** The header's Test in game (enabled when the latest edits pass the check) hands the game the checked data, unsaved edits included; the game plays a skirmish against a computer player on the open map (or the last one played, or the first skirmish map) with that data in place of its own, and the editor waits. Leaving the match restores the game's own data and brings the editor back as it was. Unsaved edits to a map's own documents are not played yet (the map package is read from disk; the map editor brings that); the match tools are the debug overlay's (F9: speed, reveal), and testing cheats come with the editors that need them. `capture-screens --only editor` plays one such test and checks both data swaps.

## M2. The data editors (decided by Claude while Jiri was away, 2026-10-16 — review)

M1's generic forms already edit every field of every element. M2 adds what a form cannot show, per editor, as an **Overview** beside Form and JSON, and links the elements to each other:

- **Links everywhere (review).** Every id field opens the element it names, in its own editor; the header's Back and Forward walk that trail, so "open the hero's ability, tweak it, come back" is two clicks.
- **Units and heroes (review).** A stat card (health, armour, damage, attack speed, range, speed, sight, supply, cost and training time; a hero's level table), the abilities it binds with their hotkeys (open each; bind another from a picker, with the next free hotkey and column; create a new ability and bind it in one step), and what trains it.
- **Buildings and items (review).** What a building trains and researches (open, add, remove), its cost, build time and footprint; an item's stats and who carries or sells it.
- **Abilities (review).** The old spell studio's form keeps its design: a rank table (parameters by rank, add a rank or a parameter), the cast's timeline (prepare, channel, recover, cooldown) drawn to scale, targeting in words, and which units bind it. **The encounter stage** (cast on test targets in the viewport with the real simulation) is the largest piece and follows once M3 and M4 are built (built 2026-10-17, below).
- **Effects (review).** Its layers at a glance; previews come with the encounter stage.
- **Races and rules (review).** A race's roster (its units, heroes and buildings, opening each) and starting setup.

**Built (2026-10-16):** `overview.rs` (the Overview view, opening by default where it exists), id fields' → link and the header's Back and Forward (`shell.rs`, `forms.rs`). Units: stat card, a hero's levels, abilities (hotkeys, unbind, bind from a picker with the next free hotkey and column, New ability… starts the create dialog in Abilities), trained by. Buildings: stats, Trains and Researches (open, add, remove), built by. Items: stats, found in. Abilities: rank table (edit cells; add a rank or a parameter; remove a rank), the cast to scale, targeting in words, bound by. Effects: duration, layers on a timeline, used by. Races: roster by group and starting setup. **The encounter (built, review):** instead of the old studio's stage inside the editor, each unit under an ability's "Bound by" has **Try it**: a test match (Test in game, unsaved edits included) where that unit stands 24 cells from your start towards the middle, a hero at its third level, with three of its race's units as allies and three of the map's creeps ahead (`canopy_sim::crowd::encounter`). It is the real game, casting from the real command card; the debug overlay's speed control slows a match.

**Built (2026-10-17, review): the ability stage**, Jiri's request, the old spell studio's encounter stage carried over as it was. An ability's tab has a **Stage** view beside Overview, Form and JSON (and each unit under "Bound by" has **Stage**, which opens it with that unit casting). Try it stays.

- **A fixture around the real game, not a second implementation** (`canopy_sim::encounter`, so it is tested headless). The content of the last check that passed (unsaved edits included) gets preview copies of the caster and target units: no training, levels, items or abilities of their own, never heroes (the old studio's default), and their weapons only when "Units move and fight" is on (a neutral camp's targets keep theirs and defend their camp; a caster keeps its own for a weapon-cast ability). The caster has 1,000 mana without regeneration and binds the ability alone, on Q, at the chosen rank; the ability costs nothing, has no cooldown and does not autocast. A flat 256-cell sandbox map with no starts: the caster at a point facing east, the first target `distance` cells east of it, the others on a circle of `spacing` around the first, each facing the caster. The targets are allies (player 1), enemies (player 2), nobody (a neutral camp of them, aggro 8, leash 18) or absent (self).
- **Settings** (the panel on the left): caster unit, target unit, relation, count 0–8, distance 1–30, spacing 1–8, rank, starting mana, caster and target health (percent of their maximum, instead of the old absolute numbers, since the copies keep their real health) (review), units move and fight, targets start as corpses. **Presets** as the old studio's (Single enemy, Few enemies, Single ally, Few allies, Fallen allies, Neutral camp, Empty ground, Caster only), independent of the ability; they set distance 8, spacing 3 and wounded allies (50 %) so heals show (review). A new stage starts from a suggestion: a unit that binds the ability casts, the default race's first soldier stands as the target, and the scene follows the ability's aim (enemies, allies, the caster alone, a group for areas and auras; a fight for passives without an aura) (review).
- **Transport**: Cast (Q), Interrupt, Reset (R), Play/Pause (Space), +1 tick, speed ¼ ½ 1× 2×, the time in seconds and ticks. Each Cast starts a fresh take (a new world from the fixture) and issues the cast order through the game's own command. Self spells and passives (which run, not cast) start at once; unit and point spells wait for a click in the viewport (the nearest unit body to the pointer's ray, or the ground under it; the ground shows the game's aim ring and range), Escape cancels, and Q again aims at the first target. **Interrupt is the Stop command** on the caster (a cast before its release is cancelled and refunded, a channel ends) instead of the old one-second stun: the simulation has no stun without an ability that carries one (review).
- **Seeking replays**: a take records its interruptions at their ticks; going back builds the world again, casts again, replays them and steps to the tick, presenting every tick, so any moment shows exactly as stepping straight there would (a test checks the fingerprints). A take stops after its course: prepare, channel, delivery, recover and the longest lasting effect, plus two seconds, at most a minute (the old studio allowed five) (review). An edit to the ability (or anything the check passes) replays the take to the same tick, so a change shows at the same moment; a change of settings starts over, as in the old studio.
- **Timeline** under the viewport: lanes Animation (Turn, Prepare, Channel, Recover, a cancellation), Impacts (every event with its amount) and Statuses (each status from its application to its end, dispel or the holder's death; summons), drawn to scale under a playhead that seeks on click and drag; clicking a span seeks to its start. **Events** lists every event (tick, event, amount, unit, status) and seeks on its tick. What the simulation refused (out of range, a target that does not match) shows in red. No cooldown marker.
- **The view**: the simulation runs on the editor's thread (a take's world costs about 8 ms to build, a tick far less) and the stage draws it as the game does: the presentations interpolated, effects and projectiles, health and mana bars, the caster's selection circle. Drag turns the camera, right or middle drag pans, scroll zooms; it frames the units until it is moved; Fit (or a double-click) frames them again. Corpses show as faint rings (the game draws a body only while it falls).
- **Ground**: the zinc stage by default: the sandbox's ground in one material (the first biome's rock) tinted so its texture averages a dark neutral grey, without the forest around the map, in the zinc stage's light (review: a tinted texture rather than a flat colour, since the terrain renderer draws textures; it reads as a neutral stone floor). Any biome's ground and light is a switch away, for the in-game look.
- **MCP `encounter`** runs the same take headless for agents: an ability, a preset or any setting, an aim (the first target by default, or a unit or a cell) and an optional interruption tick; it answers with the settings used, every event, the refusals, the timeline and each unit's health, mana and statuses at the end. It waits for the check, so unsaved edits play.
- `canopy capture-screens --only editor` shows a projectile spell caught in flight and a hero's area spell on a few enemies (`editor-ability-stage`, `editor-ability-stage-area`).
- **Not carried over**: the old studio's caster and target locomotion, nature and hero overrides, starting statuses (`initialStatuses`), the seed setting, the caster-only, target-only, effect-only and environment view modes, autocast and attack interventions.

## M3. The map editor (built 2026-10-17; its brush editor removed by D81, 2026-10-21)

**Settled (Jiri, ahead of the build):**

- **Brushes that change the terrain directly**, as in Warcraft III's editor: raise, lower, flatten, smooth, cliffs, paint. No editable landform objects for now. Procedural or stored objects ("paint a layer called island and get a good island") come later, once everything can be edited by hand.
- **The finish line:** with these manual tools we can build Echo Isles, and M3 ends with a good, solid, playable 1v1 map authored in the editor with everything a map needs: creep camps, forests, resources.
- **No symmetry tools** for now.
- **Start locations** place the player's main hall location and its amber resources, properly oriented. Nothing more by rules yet.
- **No new ground cover** (moving grass, decals, foliage) for now.
- **Mission scripting is Lua.**

**Built (2026-10-16/17):**

- **The Maps editor** (`crates/editor/src/map/`): a map opens in a viewport drawn with the game's own renderer and its biome's light (right/middle drag pans, Alt turns, scroll zooms). **New map** in the library makes a package of any size and biome: flat dry ground in grass, every ground material as a paint layer, players 1 and 2 in opposite corners.
- **Brushes** (one undo step per stroke, the viewport following as you paint): Raise, Lower, Flatten, Smooth, **Cliff** (hard steps of one cliff level), **Ramp** (drag from a cliff top to the ground below: a straight walkable slope as wide as the brush), Paint (soil, grass, rock or any paint material; cliff faces follow the slopes by themselves), Water (flood to a level, Shift drains), **Trees** (harvestable trees on Warcraft III's staggered lattice, two to every 5 × 5 cells as imported maps have them, never in water or on cliffs) and **Props** (rocks, logs, mushrooms, flowers: decoration that blocks nothing; trees and props clear apart).
- **Clicks:** **Amber** places a five-crystal site on the building lattice, its hollow facing the nearest start; **Camp** places creeps of a chosen strength (easy, medium, hard by the Warcraft levels) with their camp, on a ring wide enough for their bodies; **Start** places the next free player with a level pad, its amber 26 cells towards the middle and the hall's door turned to face the middle. **Select** picks a start, mine, creep or tree; Delete removes it (a creep takes its camp with it).
- **The check** loads a map with unsaved edits too: the map rules, the starts' playability, and whether armies, a hero (twice a warrior's size) included, can walk from the first start to every start, camp and amber site around cliffs, deep water and trees, through lanes at least 7 cells wide (`canopy_sim::spawn::connected`).
- **Test in game** plays the open map with its unsaved edits. **Write preview** (map tools, or MCP `map_preview`) draws the map picker's `preview.webp`, the old game's illustrated atlas (elevation, water, woodland, amber, camps, starts; `map/preview.rs`).
- **MCP map tools** for agents: `create_map`, `map_stroke` (every brush along a line; removed with the brush editor, D81), `map_place`, `map_remove`, `map_info` (layout, a coarse height grid, unreachable sites, problems), `map_picture` (the map from straight above as a PNG) and `map_preview`.
- **Amberleaf Crossing** (the M3 map, authored with brush strokes) and the **Warcraft map importer** (`warcraft/`, D56) are gone with the old maps (D82, 2026-10-21): every map is made of blocks.
- **StarCraft II maps** (`starcraft/`, the Maps library's **Import StarCraft II map…**, MCP `import_starcraft`; D84): a melee map (`.SC2Map`, or a Battle.net cache `.s2ma`) becomes a block map. The dialog lists the melee maps found on the machine (the game's Maps folder and the Battle.net cache). The archive is read by our own MPQ reader (formats 0–3, zlib, bzip2 and implode). One of their cells is one of our blocks (4 × 4 cells), the scale their buildings and units have to ours (town hall 5 × 5 to our fort 20 × 20, barracks 3 × 3 to 12 × 12, depot and turret 2 × 2 to house and tower 8 × 8, marine radius 0.375 to 1.5), so a map keeps its proportions, ramps their width for armies and mains their room for halls, with nothing widened or padded: their cliff levels (`t3SyncCliffLevel`) become block levels cell for cell, their ramps ramp blocks falling the way their cliffs fall (a diagonal ramp's teeth cut), their chasms (level 0) deep water; the whole map, its border included, at its own size (their largest, 256 cells, is our largest, 1024); the playable area their camera bounds; plateaus' turning corners cut at 45°. Start locations become starts, mineral fields amber nodes and geysers substance deposits on the building lattice where the game allows them; rocks, towers and decoration are left out. The game's own checks (starts, reachability) run on the result and their notes come back with it.

## The block editor (D80, first build 2026-10-20)

Maps are shaped in blocks, and the world will be generated from them. This first build is the blockout alone, to get the feel.

- **Blocks** (`canopy_content::map::blocks`, `terrain/blocks.grid`): columns of 4 × 4 cells, stacked in whole cliff levels of 3 m (levels 0–7; flat ground starts at level 1, so water and hollows have room below). Each column has a kind (ground, ramp, forest floor, rock, shallow or deep water) and an optional diagonal cut, whose triangle takes the level and kind of the neighbours beside it. Every edit makes the map's heights, water and closed cells from the blocks (`Blocks::apply`): a raised column keeps its whole top and its cliff falls in the lower neighbour's first cell; a ramp slopes one level across its column towards its lowest neighbour, gently enough to walk; forest floor and rock close their cells. The simulation reads only those grids, so Test in game plays the blockout.
- **The view** (`crates/editor/src/world/`): a map opens in the block editor; the renderer draws the blocks instead of the terrain (`canopy_render::blockout`), flat colours with an outline around every block face and walls split at every level, so each cube reads as a cube. Ground shades from low greens to high sand by level; ramps, forest floor, rock and water have their own colours.
- **The tool strip**: a floating, bordered bar of tool icons at the foot of the view (things: Select, Place; shaping: Raise, Level, Paint, Ramp, Cut, Round; surface: Cells, Face), the chosen one highlighted, its name, key and use on hover; above it a second strip holds the chosen tool's settings (box, brush or lasso and the brush's size, the kind, the face, what Place puts down with its amber or strength, what Select holds and its Delete). **Place**'s picker is the catalog of everything that can be placed (`world/catalog.rs`, made from the content, so new definitions and scenery appear by themselves): a search over everything, then categories — Buildings and Units (by race, then the neutral ones), Camps (by strength), Special (player starts 1–8, which move the start when the map has it; a single amber node with its amount; the substance deposit) and World (scenery by its category: plants and trees, landmarks, …) — each a grid of icons; units and buildings of a race are placed for the owner chosen beside the picker (none, or players 1–8). Everything snaps as the simulation requires: a building's footprint edges, a start and an amber node on the 4-cell building lattice (the simulation refuses anything else), units and camps on cell centres, scenery too; what may stand anywhere snaps block by block or, with **X** (or the strip's 4 cells / 1 cell), cell by cell. Place shows a ghost of what it puts down (its model, at the snapped spot, with its footprint) and checks it as the game does (`canopy_sim::spawn::start_problem` and `site_problem`: a start's room, dry and gentle ground for every race's fort and workers, at least 8 cells inside, 20 from another start; a unit or building on open ground in the playable area, a building's foundation flat and clear of other buildings and starts): where it may not stand the ghost is red with the reason, and a click places nothing. Dragging a selection moves it at once, snapped as it will land (whole blocks when it holds a building, start or node), red with the reason where something may not stand, and a drop there is refused. With symmetry the mirror's twin goes to the next player. **Select** (the default tool) picks what a click is nearest (Shift adds or removes), a rectangle dragged from empty ground selects everything in it, a drag from the selection moves all of it (each camp once), Delete removes all of it. Kinds and faces are pickers: a button with the current choice's picture opens a grid of every choice's picture above it (`world/palette.rs` makes them from the cooked pack: the biome's ground texture for each kind, its colour for water, each face's cliff texture, the portraits of a start's hall, the amber mine and the strongest creep), with the kinds' number keys in their corners. A third floating bar at the top of the view hides or shows the maps library (hidden by default) and the map's panel, cycles symmetry (Y) and switches what it shows: the blocks or the generated world (G); **Split** (V, and again back): the blocks and the generated world side by side under one camera, edited in either pane (the one under the pointer), the world made again two seconds after the last change and never during a drag, a small spinner in its corner while it waits (a second viewport draws it); or **Pathing** (H, and again back): every playable cell flat at its height, green where ground units can walk (open, with a neighbour within a climbable step, as the simulation moves them) and grey where they cannot, outlined cell by cell, with grey walls where a step is too high to climb. The keys work wherever the pointer is. **The map's panel** (right, `world/settings.rs`; the block editor has no left panel any more) shows, with nothing selected, the map's settings: **Meta** (name and description, in package.json; the map picture, drawn again on a click or replaced by an uploaded image cut square to 512 pixels; **Size**: presets Small, Medium, Large, Huge or playable width, height and border in cells, applied at once: the map grows or shrinks round its playable area, keeping its blocks and everything on them, new ground open inside and forest in the border; a map is any multiple of 32 cells from 128 to 1024) and **Visuals** (the biome, chosen from a picker with each biome's picture and description; the weather: none, rain, snow or god rays; the time of day: dawn, day, dusk, night or any hour, and whether time passes from it during the match, on by default). With something selected it shows what that is: a start's player, race, cell and facing; a unit's, building's or node's name and icon, id, kind, owner, cell, facing, footprint, amount, health, construction, stock, level and its camp (creeps, levels, home, aggro range, leash, loot); a piece of scenery's piece, cell, turn and scale; several selected are counted. the status line (the block under the pointer) sits at the view's top left.
- **Tools** (keys while the pointer is over the view): **Raise** Q (drag an area one level up, Shift down), **Level** W (the area takes the level of the block the drag began on), **Paint** E (the chosen kind; 1–7 pick it), **Ramp** R (drag from the top of a cliff to its foot: the ramp falls that way, snapped to eight directions, the brush wide; Shift removes), **Cut** T (click near a corner; again removes), **Cells** C (paint kinds cell by cell, for shores and frame edges at any angle; Shift clears), **Face** F (the face the cliffs under the dragged blocks take, from the biome's faces; Shift: the biome's own), **Place** P (a start with its amber, an amber site or a creep camp), **Round** O (cuts the turning corners of the plateaus under the drag at 45°, so outlines lose their boxes; Shift uncuts). **Symmetry** (Y cycles: off, point, left–right, top–bottom) makes every edit and placement in the mirror too, previewed in amber, for fair maps. Raise, Level, Paint, Face and Round work on a dragged box, along a brush stroke, or inside a lasso (the loop a drag draws; Cells too), **B** cycling them; **[ ]** size the brush (blocks, or cells for Cells). While a drag is under way the map shows the edit live, blocks or generated world (none of it in the documents until the drag ends); the view also outlines the blocks or cells a drag will change, the ramp's fall as an arrow, and the status line names the block under the pointer, its painted cell, a ramp's fall and its face. Each edit is one undo step: the blocks, painted cells and closed cells whole, heights and water as patches over what changed.
- **Every map is made of blocks (D82)**: a new map starts as flat level-1 blocks; a package without blocks is refused.
- **Select** S picks a start, an amber site, a camp or a placed prop: a drag moves it by whole cells (a camp member takes its whole camp and home, an amber crystal the rest of its site), Delete removes it (a camp member its camp).
- **Playable area**: a strong amber line on the ground round the playable area, its size at a corner; the panel sets its border all round or side by side, in whole blocks (never under 64 cells across).
- **Map › Write map picture** writes the map picker's `preview.webp`.
- **The brush editor of M3 is removed (D81)**: maps are made in blocks.
- **Captures**: `canopy capture-screens --only blocks` edits Frozen Dream and Frost Hollow in every view.
- **Generated view** (G, or the view switch at the top of the view): the world the game generates from the blocks (D80): generated cliffs, ground, decals and scattered scenery, with the biome's light. The tools edit the blocks in either view.
- **MCP `map_blocks`**: what the block tools do (flat, raise, lower, level, paint, face, unface, ramp, unramp, cut, uncut, cells, uncells, fill) over a box, along a line or inside an outline in world cells; `tools/maps/frost_hollow.py` authors a whole scene with it.
- **Block maps**: `tools/maps/blocks_map.py <map> <out.png> [--reach]` draws a map's blocks from above (levels, ramps, closed ground, cliffs, starts) and with `--reach` where an army reaches from the first start, with the margin it keeps from cliffs: the quickest way to find a lane the start check calls too narrow. `tools/maps/frozen_dream.py` authors a whole three-level map with symmetry on.
- **Look-dev comparison**: `tools/look/compare.py <regions.json> <render.png>` measures a render against its target region by region (colour, ΔE, contrast, detail) and writes a heat map; `tools/look/frost-hollow.json` holds Frost Hollow's target, camera and regions.
- **Next** (D80): organic frame outlines and edge dressing, landmarks as blocks, set pieces.

## M4. The asset editor (built 2026-10-17)

**Settled (Jiri):** the asset editor is a tool for us, mostly for agents: what makes new assets quick to create and to author well into the game. Its scope is mine to decide from the asset format (not overdone). **Players never bring their own models, icons or other assets**: player packages use the game's pool only. Built right after M3.

**Scope (decided by Claude, review):**

- **An asset's Overview:** its model in the viewport, playing any of its animations (the clips the cooked model has, and which semantic each serves); its files (present, missing, size) and its kind, display and team colour settings in the form.
- **Import:** a glTF model (or an image, for icons and portraits) becomes a new asset folder with its `asset.json` from the kind's defaults; MCP has the same tool for agents.
- **Cook from the editor:** the changed assets are cooked into the pack (incrementally) and the viewport reloads, so a new model is seen without leaving.
- **Unused assets:** a list of assets nothing names (definitions, scenery, effects, maps, biomes, interface), and deleting one removes its whole folder on save (undo before saving brings it back).

**Built (2026-10-17, review):**

- **An asset's Overview** (`overview.rs`): its kind, race, scale in game, animation profile and team colour; its files, each present with its size or marked missing, working files (sources, recipes) noted as never cooked; its animations (semantic, clip, looping); and what uses it. The preview under the inspector plays any clip the cooked model has (or its rest pose).
- **Import** (`assets.rs`, the Assets library's **Import…**, MCP `import_asset`): a `.glb` becomes a model asset (unit, creature, building, tree, foliage, prop or bridge) as `geometry.glb`, its `asset.json` prefilled: the clips under the semantics they are named after (idle, walk, run, attack, …, the looping ones looping), its `socket_*` nodes as sockets, a building's shading. A `.png` becomes an icon, interface image or texture as `image.png`. The folder is written at once, as files copied in by hand would be.
- **Cook** (the Assets library's **Cook**, MCP `cook`): runs `canopy-cook` as `just cook` does, in the background (the editor only runs from the repository, so the cooker stays out of the game binary); when it finishes the viewports and map scenes open the new pack.
- **Unused assets:** the Assets library's **Only assets nothing names**, and MCP `unused_assets`: assets no document names (as an id or a pack entry, `asset.x/image.png`), nor the repository's config or code (code that forms ids from a pattern, `asset.interface.campaign.{race}`, counts). Deleting an asset (now offered for assets too) removes its listed files and its folder when that leaves it empty, on save; undo brings it back until then.
- **Not built:** retargeting animations, editing materials or team colour masks, and generating art. Those stay with the art pipeline and its agents.

## M5. Players' content (decided 2026-10-16: aspirational for now)

**Settled (Jiri):** players' content is a goal for later, not now. The game is not yet one people extend, so:

- **Only we author, and only the base package.** Players do not get the editor; when they do, it will be for maps only at first, with more unlocked later.
- **No sharing yet**, as a consequence: nothing to share while players cannot edit.
- **Safety: something reasonable**, aimed at our own authoring; the Lua sandbox audit waits until players write scripts.
- **Every version loads:** no version gates on packages or maps for now (they would only slow us down).
- **No mods and no custom maps yet.**
